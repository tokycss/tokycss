# Responsibilities & Limitations

Toky CSS aims to provide strong foundations, but it is important to understand what the framework does not do.

| Toky CSS Is Not                     | Why                                               |
| ----------------------------------- | ------------------------------------------------- |
| A component library                 | Components are intentionally left to your project |
| A UI kit                            | Visual design remains your responsibility         |
| An accessibility guarantee          | Every project requires accessibility testing      |
| A browser compatibility guarantee   | Browser testing is still required                 |
| A replacement for design review     | Good design decisions remain human decisions      |
| A replacement for usability testing | Real users still provide the best feedback        |
| A JavaScript framework              | Toky CSS focuses on CSS only                      |
| A no-thinking-required solution     | Projects still require thoughtful implementation  |

Toky CSS provides flexible foundations and sensible defaults.

How those foundations are applied ultimately determines the quality, accessibility, usability, and maintainability of the final product.
