# Compatibility

Toky CSS is designed to work wherever CSS works.

Because the framework is distributed as a single CSS file, it can be used in static websites, content management systems, JavaScript frameworks, server-rendered applications, design systems, dashboards, internal tools, documentation sites, and many other frontend environments.

Toky CSS does not require a specific framework, programming language, build process, bundler, or development workflow.

Simply load the stylesheet and start building.

## Browser Support

Toky CSS prioritizes CSS features that meet Baseline Widely Available status whenever possible.

Modern CSS capabilities such as:

* `@layer`
* `clamp()`
* `color-mix()`
* `oklch()`
* `light-dark()`
* `prefers-color-scheme`

allow Toky CSS to provide functionality that previously required preprocessors, plugins, or JavaScript.

When newer CSS features are used intentionally, they are documented in the relevant sections of the documentation.

## Platform Compatibility

Toky CSS is designed to be a good citizen within existing workflows rather than forcing a new one.

Whether you are building a marketing site, SaaS dashboard, documentation portal, ecommerce storefront, internal business application, or design system, Toky CSS aims to fit naturally into your existing frontend stack.

Our goal is to give Toky CSS users a smoother workflow experience. Creators, platform owners, tool authors, and community contributors are always welcome to share suggestions, ideas, and opportunities for deeper collaboration/integration.

## A Note About Compatibility

Browser support continues to evolve.

While Toky CSS provides thoughtful defaults and modern foundations, it does not replace browser testing, accessibility testing, performance testing, or project-specific validation.

Always verify that your implementation works for your users and your requirements.
